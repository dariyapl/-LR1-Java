# Лабораторна робота №1
## Варіант:
Номер у списку групи: 12

Розрахунок варіанта:

V = N mod 3

V = 12 mod 3 = 0

Отже, мій варіант - V = 0: Система управління замовленнями.

## Про проєкт
У цій лабораторній роботі реалізована проста система для роботи зі статусами замовлень.
Для статусів використовується `sealed interface OrderStatus`, а самі статуси реалізовані через `record`

Є такі статуси:
- Pending
- Paid
- Shipped
- Cancelled

## Використані технології:
- Java 26
- Maven
- JUnit 5
- IntelliJ IDEA

## Реалізація

### OrderStatus

OrderStatus - sealed-інтерфейс, який дозволяє використовувати тільки такі типи:

- Pending
- Paid
- Shipped
- Cancelled

### Pending
Статус замовлення, яке ще очікує на обробку.

### Paid
Містить:
- `paymentID` - ідентифікатор платежу
- `amount` - сума платежу

Є перевірка, щоб:
- `paymentID` не був `null` або порожнім
- `amount` не був `null`
- сума була більшою за 0

### Shipped
Містить:
- `trackingCode` - код відстеження
- `dispatchDate` - дата відправлення

Є перевірка, щоб:
- `trackingCode` не був `null` або порожнім
- `dispatchDate` не був `null`

### Cancelled
Містить причину скасування замовлення.
Перевіряється, щоб причина не була `null` або порожньою.

## OrderProcessor

У класі `OrderProcessor` реалізований метод для обробки статусу замовлення.

Для цього використовується:
- `switch expression`
- `pattern matching`
- `Text Blocks`

Для кожного статусу формується відповідний текст з інформацією про замовлення.

## Валідація

Перевірки виконуються безпосередньо в конструкторах `record`.
Якщо передані неправильні дані, викидається: `IllegalArgumentException`

## Тестування
Для тестування використовується JUnit 5.

Тести перевіряють:
- правильне створення статусів
- некоректні значення
- null
- порожні рядки
- від'ємну або нульову суму
- роботу всіх гілок OrderProcessor

Тести можна запустити через IntelliJ IDEA або командою:

```bash
mvn test
